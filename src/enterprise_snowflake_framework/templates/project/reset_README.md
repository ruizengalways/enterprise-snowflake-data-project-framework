# Reset

Reset discards and recreates a development/UAT/candidate implementation so it can be bootstrapped again from a known source of truth.

Typical targets:

- candidate Silver history tables
- candidate Streams
- candidate Tasks
- temporary validation objects

Reset is not the default way to repair the active production version.

A production defect should normally create a candidate version, replay/backfill that candidate, validate it and then cut over. Reset SQL generated by the framework must make every destructive object operation explicit for engineer review before execution.
